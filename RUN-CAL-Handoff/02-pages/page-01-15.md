# Page 1–15 Specification

## Page 1 — Launch + Login (existing prototype)

RUN|CAL wordmark; username; numeric six-digit Access PIN; show/hide; reset; create athlete profile; Light/Dark/System; responsive. Production must use server verification, hashed PIN, generic errors, rate limiting, temporary lock, secure session, and audit events. No PIN is ever readable by admins.

## Page 2 — Create Athlete Profile

Five-step wizard: **Account → Personal → Running → Goal → Review**, then success and back to Login with username prefilled. Account: unique normalized username, PIN/confirm, optional 1:1 image. Personal: names/display name, birth date, sex used for sport context, height, weight; contact/location optional. Running: experience, typical weekly distance/runs, preferred distances, Stryd Yes/No and optional Single/Duo/Unknown. Goal: objective, optional target/date/race. Create UUID plus display athlete ID. Emergency contact and Drive connection move to Settings. CP/known thresholds may be added as optional known baselines, with source/effective date; never guessed.

## Page 3 — Home / Navigation

Mobile bottom nav: Home, Training, central Import action, Calendar, Profile. Desktop uses collapsible sidebar. Show greeting/date, quick actions, interactive five-component Daily Recovery, latest run with GPS mini-map and key metrics, post-training comment/replies, weekly summary, next race, AI baseline progress/status, role-aware links and empty states. Home is concise; Page 4 owns deep analytics.

## Page 4 — Running Dashboard

Default four-week range with 7d/4w/12w/custom. Summary: distance, time, run count, pace, HR and power only when available. Charts: weekly volume, pace, HR, power, recovery, load vs recovery; recent activities and race context. Stryd snapshot includes power, W/kg, LSS, LSS Balance (Duo/data-dependent), Form Power, Form Power Ratio, Air Power. AI card shows baseline collection before readiness, then weekly evidence/why/proposal. Do not show fabricated load, readiness, or race-readiness percentages.

## Page 5 — Import FIT

Select/drop `.fit` → validate readable/running/timestamp/duration-distance → compute hash and duplicate check → parse preview including route/device/data-availability → explicit confirm → persist immutable original → normalized activity/records → analytics. Possible duplicates link to existing and do not auto-create. Unsupported/corrupt files show clear errors. Track import job, parser version, warnings and field provenance. Drive sync is Phase 2.

## Page 6 — Activity Detail

Header/type/edit metadata; GPS route; distance/time/pace/HR/power/elevation/calories/cadence when present; pace/elevation, HR and power charts; HR/power zones only with an effective approved zone model; Stryd selector; splits/laps; pre-run recovery; Session RPE 1–10; athlete/coach activity comment thread; threshold-test marking. Missing metrics display unavailable—not 0. Planned-vs-actual is included when Page 11 planning is enabled.

## Page 7 — Stryd Running Power (conditional)

Visible only when athlete enables Stryd; Page 6 still shows per-activity power if detected. If disabled but data is detected, offer enable/not now—never auto-enable. Show Current CP, W/kg, source, effective date, CP/weight development, configured power zones, running power, LSS, optional Duo LSS Balance, Form Power/FPR and Air Power trends. No CP means import succeeds but zone analysis is unavailable with a setup CTA. Disabling hides current UI but never deletes history.

## Page 8 — Training Load & Trends

Default eight weeks; training context/phase/race countdown; weekly distance/time/activity volume; Session RPE trend and `duration minutes × RPE` AU; intensity distribution using only approved effective zones; recovery overlays; load vs recovery; optional Stryd response; weekly AI evidence/review after readiness. Keep RPE, HR-based, and power-based load as distinct views—do not add them together. Primary load, HR load, power load, status thresholds, monotony/strain/ACWR/ramp formulas are BLOCKED-SOURCE.

## Page 9 — Recovery & Readiness

Fast daily check-in: Physical Freshness, Sleep Quality, Muscle Recovery, Physiological Freshness (with plain-language help; General Wellbeing may be a future label), Hydration; each 1–5. MVP overall = arithmetic mean of available required five metrics. Optional note and sleep duration; prepare optional resting HR/source fields. Show history, component trends, baseline comparisons and training context. Avoid medical or injury diagnosis and do not treat missing entries as poor recovery.

## Page 10 — Training Log

Lightweight diary linked to activity/planned session: training type, Session RPE, athlete note, coach comment, planned-vs-completed; hydration before/during/after; optional pre-run meal, during-run carbohydrate g/h, post-run nutrition and notes; environment when known. No all-day calories/macros, food database, supplements, or AI nutrition coach.

## Page 11 — Calendar & Race Goals

Calendar and Races modes. Planned sessions contain date, type, distance/duration, target by pace/HR zone/power zone/RPE, structure and notes. Distinguish planned from completed and show planned-vs-actual. Races support name/date/distance/type/location, A/B/C priority, target time/pace and optional approved power target; multiple races, with A as primary context. AI changes follow Propose → Explain → Approve/Modify/Reject → Update; never auto-apply.

## Page 12 — Athletes / Coach Dashboard

Coach/Admin only. List assigned/authorized athletes with objective, phase, next race, recovery summary, training status and last run. “Needs Review” signals only—never athlete rankings or unsupported injury risk. Triggers can include falling recovery, rapid load only with approved threshold, unexpectedly high RPE, missed plan, inactivity against plan, new comment, or pending AI review. Search and filters: objective, phase, Needs Review, upcoming race. Reuse existing athlete pages in explicit `Coach View — Athlete` context.

## Page 13 — Messages & Coach Communication

Athlete ↔ assigned coach/admin contextual text conversations with timestamps, read/unread, badge/history and references to activity, planned session, race, recovery or AI review. Activity comments remain a separate activity-bound model. In-app notifications MVP; push/email Phase 2. No group chat, calls, presence, typing indicator, reactions, social feed or direct AI participant.

## Page 14 — Settings & Data Connections

Sections: Account/PIN; Athlete Profile; weight history; training objective/phase history; devices/Stryd; CP/Wkg/history; power zones; HR zones/history; Testing & Protocols; Drive connection/status (Phase 2 sync); notifications; appearance; **Language (English / ไทย)**; privacy/data; original FIT storage (mandatory ON in MVP); admin membership/assignment/reset controls. Folder identity is Drive folder ID. Historical data survives device toggles. Full automated export/delete may be Phase 2 but ownership must exist now.

### Testing Protocols Calculator — Athlete Profile subpage

This is a subpage of Page 14 / Athlete Profile, not a new primary numbered page. It provides the approved LTP, LTHR, Pace Zone, HR Zone and Hydration test calculators from `RUN-CAL-TEST-PROTOCOLS/2026.09.03`.

Flow: choose protocol → enter raw test inputs → validate → calculate a preview → save test record → optionally select **Apply proposed Pace Zones**, **Apply proposed HR Zones**, or both → show an explicit confirmation comparison → only then create a new effective-dated Athlete Profile zone record.

The calculator result and test history do not automatically affect Training Load, Recovery, Readiness, AI context/proposals, Calendar, FIT metrics, CP, W/kg, Power Zones, or historical activities. The only permitted apply action is an explicit, confirmed update of the Athlete Profile's Pace Zones and/or HR Zones. The confirmation must show current versus proposed boundaries, source test/protocol/version and effective date, with `Cancel / Keep current` as the safe default. A declined proposal remains a saved test record and does not change the profile. No result is applied retroactively.

Searchable role-aware Help/User Guide, onboarding and troubleshooting, privacy/ownership explanation, data-quality meanings, import errors, missing metrics, AI/readiness limitations, app/build/protocol/parser versions, support route and release notes link. Provide every Help article in the active app language (English or ไทย). Include “Setting Up a New Team”: Create Workspace → Add Workspace Admin → Invite Coaches → Create/Invite Athletes → Assign Athletes → Configure profiles → Configure approved CP/LTP/LTHR/Zones → Configure FIT source → Verify permissions → Ready.

Required FAQ: Can Team A see Team B? Can a coach join multiple workspaces? What happens when an athlete changes teams? Does historical data move? Can Platform Owner see athlete content? Why is Stryd hidden? Why is a metric unavailable? Why is AI not ready? How are old activities calculated after CP/weight changes? Where are originals stored? How are formula/protocol versions shown?
